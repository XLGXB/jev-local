# SemDecide local CLI

`jevlocal-semdecide` (or `python -m jevlocal.integration.semdecide_cli`) runs bounded local typed decisions in one owned Windows worker. Its unchanged default/native route is uncalibrated Laya/Kev; an explicitly configured `state_json_advisory_v1` route is calibrated for Score only. Neither route authorizes action, executes model text, trains, downloads, or falls back to an online model. An active isolated virtual environment with `include-system-site-packages=false`, Windows Job Object admission, and cleanup are required; base/shared environments and other platforms fail closed.

```text
jevlocal-semdecide --runtime-config C:\absolute\native.json --input C:\absolute\batch.jsonl --format jsonl --max-records 64 --timeout 120
```

The runtime JSON has exactly `mode`, `backend`, `checkpoint`, `device`, `amp`, `weights_dtype`; use `mode="native"`, `backend="laya"` or `"kev"`, an existing absolute local checkpoint directory, `device="cpu"` or `"cuda"`, `amp="none"`, `weights_dtype="fp32"`. Paths may not traverse UNC, symlink, or reparse points. `--input -` reads stdin; `--format json` accepts one envelope or an array, whereas `jsonl` accepts one envelope per physical line. Envelopes have exactly `request_id`, `observation_id`, `state`, `questions` and follow `decision_deploy.protocol.validate_envelope`. Labels and extra question fields are forbidden. Input is capped at 8 MiB, each envelope at 128 KiB, records at 1–256 (`64` default), questions at eight, candidates at 16. No silent truncation.

To select the advisory route, `--runtime-config` must point to a JSON object with the exact fields `schema_version`, `route`, `spec`, `expected_identity`, `expected_fingerprint`, `expected_binding`, `expected_sources`, `expected_checkpoint_files`, `calibration`; `route` must be `state_json_advisory_v1`. The pinned local sidecar, source and checkpoint hashes and runtime identity are checked before model loading in both parent and worker, and pins are rechecked by the parent before output. Unknown routes fail closed. A config without `route` retains the six-field native behavior; there is no implicit advisory default or fallback. The Score answer uses the pinned fitted temperature; Choice and Noul remain `calibrated=false`, `temperature=1.0`. The outer `route` metadata on each advisory output row records its fingerprint and calibration hash with `advisory_only=true`, `execution_authorized=false`, `qualification_status="not_qualified"`. The standard five-field `reply` remains unchanged. Metadata and selected answers confer no authority or quality guarantee.

Each success emits `record_index`, IDs, `status="ok"`, and the five-field bound `reply`. Errors emit the same index/IDs, `status="error"`, and a stable `error.code`, without exception text. Index zero with null IDs denotes a batch or worker failure. Once an advisory config is validated, even an emitted index-zero fatal row carries its advisory `route` metadata; pre-validation errors do not claim a route. In `json` mode stdout is one array; in `jsonl` mode stdout is one object per line. Worker/dependency logs and a brief summary are on stderr. Exit `0` means no errors, `1` per-record errors, `2` invocation, batch, timeout, worker, or cleanup failure. A timeout covers blocked stdin, model initialization, and inference. No success output precedes worker-tree cleanup and independent parent validation.

`--filter-question QID --keep-key KEY` may be used with repeatable unique `--keep-key` values. Every valid record must include the selected question and keys. Only successes whose selected key belongs to that explicit set are emitted. Each emitted filtered success also includes its unchanged original `input`. Errors are never hidden, and nonmatching successes produce a structured `filtered_out` event on stderr. This is a data filter, not calibration or permission. Filter criteria cannot be inferred from input state or model text.

The worker sets four process-start offline/safe-load flags and denies Python socket connect before native imports. This protects supported accidental online routes; it is not a security sandbox against arbitrary native code. The validated full runtime configuration is snapshotted into the private manifest, rather than reread from a mutable caller path. The parent owns two private gates: Windows `KILL_ON_JOB_CLOSE` assignment precedes input work; then the worker writes a bounded raw-input snapshot, which the parent independently parses and validates before admitting model work. The parent binds every returned input and decision to that snapshot, terminates the owned Job tree, confirms its active-process count is zero, and only then emits stdout. It never retries a prediction or resumes a timed-out batch.

On Windows, a venv `python.exe` may be a redirector whose process ID differs from the actual Python process. To keep Job assignment bound to the real worker, the launcher uses the same underlying interpreter with `-I -S -B -X utf8`, explicitly sets the current venv prefix and adds only its `site-packages`; base/global `site-packages` are not loaded. The focused tests verify package distribution versions and origins without importing or executing the native model.
